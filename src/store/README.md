# P2 归档、版本与恢复

`files.ts`：受限目录、内部路径边界、原子发布、来源/进程锁。`archive-store.ts`：SQLite 清单、不可混淆的公告版本、内容指纹复用、附件历史关系、任务进度、追加事件、一致性备份和新目录恢复。

`windows-access.ts` 使用异步 `execFile` 执行 whoami/icacls，15 秒超时，保留原 ACL 策略。失败输出 `WINDOWS_ACL_FAILED`（工具名及错误码）或 `WINDOWS_SID_INVALID` 后停止，未完成权限保护前不创建业务子目录；不回退为不保护目录。普通错误信息不包含 SID 或原始工具输出。

存储顺序为“文件与解析结果原子落盘 → SQLite 事务提交引用 → 写运行快照”。异常不会将未保存文件的任务写为成功；崩溃可能留下未引用文件，P2 不自动删除。按来源和公告版本保存关系，文件相同可以复用，来源不同不能丢失关联。

数据库 schema 当前为 2，打开旧 schema 1 时保留原表并新增 `archive_meta` 与追加式 `observations`。每次保存附件获得归档 ID、附件 ID 与单调观察序号；复用取最新观察，即使内容 A→B→A 也不回退到 B。来源待复核独立于解析状态，缓存、跨任务复用及恢复不能解除该限制。历史解析结果按其内容指纹保存，校验覆盖最新对象、历史任务、观察引用和公告原文。`events.jsonl` 继续追加保存处理事件。

全局与会话锁使用常驻的 `<锁名>.lock.sqlite` 和 PID 标记 `<锁名>.lock`。SQLite 排他事务覆盖整个持锁期，进程崩溃由操作系统释放，死 PID 标记只能在互斥内回收。不要删除互斥数据库，也不要混跑新旧程序。升级前用旧版备份；旧版不能读取 schema 2，回滚需配套升级前的完整备份，不能只修改 `user_version`。

所有 CLI 归档、验证和备份操作持有全局锁。备份使用 `VACUUM INTO` 后复制业务文件并生成哈希清单，不含 `private/` 和锁。恢复目标必须是新目录，校验成功后才可人工切换配置；P2 的 `--restore-check` 只做演练，不切换现用数据库。

P3 使用相同锁，将分析快照、证据包和结果保存在 `runs/p3-*/`，因此纳入上述文件备份，不改变数据库 schema。P2 校验命令核验归档数据库和附件；P3 的快照/结果校验由其加载与渲染命令执行。P3 合成数据已覆盖备份恢复，历史 P2 备份不包含后来产生的分析文件。

P5 将通知账本和回执保存在 `runs/p5-notifications/`、各次运行保存在 `runs/p5-*/`，同样自动进入文件备份，不改变数据库 schema。`notify --verify` 额外验证通知状态和回执哈希；`notify --backup` 在此校验后调用归档备份。P1 独立 CLI 从 P5 起也取得同一个 archive 锁，避免与归档、分析、通知或备份同时运行；P1 自身的来源文件仍在项目 `output/playwright/`，不因 P5 而自动迁入归档。

运行 `pnpm test` 验证重复导入、版本、损坏检测与恢复。Node 24.13.0 的 `node:sqlite` 为实验模块，版本需锁定和验证，不能消除其后续 API 变化风险。
