# P2 有头会话与人工接管

`session.ts` 以“来源 origin + 账号别名”隔离专用 Chromium 配置目录，持有独占锁；只关闭本次持有的会话，不使用或清理用户日常浏览器。

`--auth 来源ID --account 别名` 打开已登记来源主页，等待人工操作与终端 `done`。这只表示状态已保存；必须再访问实际受保护附件，才能验证其用途。没有通用的“看见 Cookie 即登录成功”判断。真实来源的登录入口、权限、跨日有效性和 CA 支持仍需要逐个实测。

`--session 来源ID --resume 任务ID` 只对相同 origin 的附件复用 Cookie。依赖浏览器 JS、证书或交互下载的场景使用 `--manual-download`，人工取得文件也可通过 `--import-file` 导入。人工浏览器下载暂标待核验来源，避免将用户误选的文件当成目标附件。

状态文件和配置目录只在受限数据根目录的 `private/sessions/` 下；不打印 Cookie，不备份会话。测试使用本地合成账号，验证重开、失效、恢复和取消；不代表政府站点真实认证已通过。
