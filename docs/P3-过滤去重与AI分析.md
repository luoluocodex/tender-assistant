## 2. 实现与边界

### 规则与公告关联

1. 从 P0 基线读取“网站开发”、广东及空排除词；没有启用同义词、预算阈值或新增站点。
2. 固定历史查询窗口，明确省外/时间外可排除；日期缺失、城市归属不明、来源查询未完成或材料不足时保留复核。缺少指定短语不会直接排除。
3. 分类采购、意向、变更、终止、结果和合同。阶段与语义相关性分别记录；结果、合同不当作新招标。
4. 使用来源公告标识保留版本；项目关联只在采购人及项目编号可靠且完全相同时进行，跨站来源分别保留。不按同名标题合并。
5. 标包从标题明确标签保守识别；未指定标包与已指定标包不直接等同，单包终止不将整个项目判终止。没有实现对正文全部标包的自动拆分。
6. 同公告新内容保留旧版本，按抓取时间记录 `current-observed` / `superseded`；关联公告按可确定的发布时间判断最新阶段。缺少精确时间或同刻冲突时待复核。
7. 更正更新项目阶段为 changed 或 needs-review；保留旧金额、旧日期及新公告，不猜更正覆盖的标包、条件和字段。尚未实现经人工确认后的有效金额/期限自动合并。
8. `--previous` 保留历史；完全相同的已验证输入复用结果，变更输入重新分析。显式 `--track site:id` 的项目更新即使缺原关键词或超原窗口也保留。该规则只能处理传入报告中的更新；**尚未实现独立于关键词的项目关联公告采集**。

### 证据与 AI 结果

- 每个分析包保存公告、正文、已归档附件文本、字段、覆盖范围、规则及三份提示词。正文按段落分块，附件保留 PDF 页码、Word 段落、Excel 单元格、ZIP 内路径。长文本完整分块，不静默截断。
- 分析文本移除 URL 敏感参数和认证头形式的内容。正文证据指纹对应分析使用的文本，原始 P1 报告另有哈希；附件保留原文件及解析结果哈希，原文件不改写。
- 公告链接保留广东站已观察的 hash 路由和公告标识参数；普通日志不输出签名和凭据。
- 规则版本包含配置与编译后处理代码指纹；输入、提示词、公司版本分别绑定。结果附实际可确认的模型入口标识。
- schema 拒绝额外字段；引文必须逐字存在且属于当前采购或公司证据类型。旧包结果、伪造引用、将采购模板当作公司资料等不能导入。
- 原始模型结果与程序降级后的结果分别保存。材料不完整时，不接受自动判为不相关；缺公司证据不接受“符合”。最终都保留人工复核状态，没有“自动批准投标”。
- 事实、推断与资料缺口分开；预算、成交、合同金额及各类日期保留类别和原文，不把缺失写成零。模型仍可能误读语义，需要人工复核。

### 真实数据发现并修正的问题

- **附件空列表不等于无附件。** 广东正文可能列出 PDF 或优先适用采购需求书，但 P1 没抽到链接；现在记录 `mentioned-but-not-indexed`。
- P2 早期任务项的 `parseSha` 为空。P3 优先使用对象表完整解析指纹兼容旧项，再兼容旧文件名指纹；校验原文件和解析内容后才导入。本轮 5 份真实附件均进入证据包。
- 广东站公告地址位于 hash 路由中。脱敏不再误删该路由及已知公告参数，保留可回到具体公告的地址。
- 非法有效日期不能被字典序比较误判为仍有效；覆盖不存在的月份和日期。
- 人工标注使用独立文件；重跑只更新 `.template.json`，不会覆盖填写后的标签。

## 4. 操作方式

在项目根目录执行：

```powershell
pnpm run analyze:p3 --help

# 正式快照
pnpm run analyze:p3 --prepare --report output/playwright/2026-09-23T11-05-57-738Z-formal/report.json

# 诊断快照，显式引用已归档的五份附件
pnpm run analyze:p3 --prepare --report output/playwright/2026-09-23T11-19-09-863Z-diagnostic/report.json --archive-job p2-73e744bf-0d47-4b5b-9336-e1644a201643

# 重复导入复用同一内容；渲染时重新校验结果
pnpm run analyze:p3 --run p3-e92eb39de5fbd08e9eab0317 --import C:/Users/14629/AppData/Local/TenderAssistant/runs/p3-e92eb39de5fbd08e9eab0317/model-response.json
pnpm run analyze:p3 --run p3-e4a64e54dcd8b04f34081fcc --render

# 其它显式参数示意：替换尖括号内容后使用
# --prepare --report <P1报告> --company-fixture <标记kind=synthetic的公司JSON>
# --prepare --report <新P1报告> --previous <前次P3任务> --track ccgp:27391875
# --run <P3任务> --evaluate <人工填写的标签JSON>
```

新任务编号由输入计算，改变代码、规则、提示词或材料得到新编号。以上编号是本次最终记录；开发过程中的早期准备快照保留为历史，不作为本轮结论。

自然语言分析目前在当前会话中完成：读取目标 `packets/*.json` 及三份提示词，生成符合 schema 的对象或对象数组，保存为 JSON 后 `--import`。不会通过脚本中的关键词正则冒充模型推理，也不会在未指定服务时自动调用 API。

数组导入逐条提交：后续项校验失败返回失败，保存原因与输入哈希；已成功项保留，清单同步实际进度。拒绝记录不保存未通过验证的模型正文。修复后可重跑。退出码 0 只表示当前操作成功；错误为 1，不能由此宣称 P3 验收通过。
