## 数据与接口变化

CLI 参数和已确认业务配置不变，内部持久化发生以下变化：

- 归档数据库 schema 1→2：保留原表，新增 `archive_meta` 和 `observations`。首次由新版 `ArchiveStore` 打开旧库时迁移，包括校验/备份等会打开数据库的命令；本轮仅迁移合成库。
- P2 项目新增可选 `sourceReviewRequired`、`observation`，后者包含 `archiveId / attachmentId / revision`。每次实际保存产生递增序号，缓存复用沿用原序号；备份保留归档 ID 与观察历史。
- 新解析标识 `p2-v2`，旧 `p2-v1` 继续可读。原文件和旧解析结果保留。
- P5 账本 payload `p5-v1`→`p5-v2`，外层 schemaVersion 仍为 1。读取 v1 先校验指纹与记录，在内存迁移；由版本匹配且校验通过的旧 P3 包补充材料元数据，缺失快照时保留未知，保存时写 v2。通知 ID、回执与转换历史不变。
- 常驻 `<锁名>.lock.sqlite` 只用于互斥，PID 标记仍为 `<锁名>.lock`；两者不进入业务备份，互斥数据库加入 Git 忽略规则。不能把常驻文件存在解释成正在运行，也不能通过删除它解锁。新旧进程不得混跑。

升级正式数据前，先停止相关任务并使用旧版生成完整备份，保留关联 P1 证据。旧版不支持 schema 2 或 v2 账本；回滚必须配套升级前完整备份并在新目录验证，不能仅回滚源码、强改 user_version 或覆盖现有归档。恢复到旧备份不会包含升级后的新记录，应另行保留这些记录。本轮没有为正式数据执行升级、降级或恢复。

## 历史材料边界

历史 P3 包与分析继续按原输入校验，历史预览不自动改写。新 P5 临期判断从正文重新提取，避免继续使用旧的错误截止字段；如要修订清单/摘要，须重新 prepare 并完成相应分析。

旧 DOCX 解析缓存不会自动重排。需要修订时，应核对原文件，显式导入或使用 `--refresh` 重新下载解析，再生成新的 P3 包。仅重跑缓存复用不会触发重解析。

旧任务仍保存人工来源待复核原因时，迁移和复用会保留该限制。若旧 Bug 已覆盖该原因且没有其他可靠记录，本轮不能从内容哈希推断来源是否已核验，需人工核查相应历史文件。没有自动追溯修订正式材料，也没有据此宣称全部历史结论已更正。
