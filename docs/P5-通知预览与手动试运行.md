## 4. 事件、时间和去重规则

| 事件 | 条件与限制 |
|---|---|
| `related-notice` | 仅已校验模型初判相关的公告；保留公告阶段、引文及资格复核提示，不声称仍可投标 |
| `project-update` | 已跟踪或此前相关公告的正文/附件内容变化，或相关更正、终止、结果、合同公告；按公告及标包处理 |
| `deadline` | 已相关/跟踪的采购公告，存在唯一、精确到分钟的响应截止时间，且无更正/多标包歧义或条件延期 |
| `run-problem` | 原 P1 查询部分完成、失败、待人工，或整体未完成；保留故障原因并去除凭据样式内容 |
| `review-required` | 未分析、待复核、临期时间不明确、旧版本或版本顺序不明等缺口汇总 |

默认临期窗口为 72 小时和 24 小时，属于当前本地预览默认值，配置在 `config/p5.json`。按北京时间解析，越过 72→24 小时边界可生成一条新版本提示；同一窗口重复运行复用。过期、仅日期、开标时间、文件获取时间和不明截止类型不会当作精确响应截止提醒。

业务事件依据用途、公告标识、内容/分析版本生成事件 ID，再将渠道、逻辑接收对象和渲染版本纳入通知 ID。抓取时刻、P3 任务号或模型运行标识变化而业务内容相同，不重复相关/临期事件。更改内容、分析结论或窗口产生新版本。采集故障与缺口汇总保留原查询运行语境，新查询或分析结果变更可能产生新的汇总。

正式/诊断分别参与去重。默认 `recipient=local-user` 是本地逻辑标识，无邮箱/群号，不能借此发送。`observations` 只记录已观察到的版本，用来阻止旧快照覆盖新内容；送达进度由 delivery 单独保存，**不推进整批采集检查点**。未知项目关联、未采集更新和跨站匹配仍受 P3 能力限制。

## 5. 状态、恢复与数据位置

数据根：`C:\Users\14629\AppData\Local\TenderAssistant`，沿用当前用户和 SYSTEM 的权限设置。

| 位置 | 内容 |
|---|---|
| `runs/p5-notifications/ledger.json` | schemaVersion + payload 字符串 + SHA-256；payload 含事件、通知、运行、观察与转换历史 |
| `runs/p5-notifications/previews/<通知ID>.md` | 确定性本地预览及可核对的内容回执 |
| `runs/p5-<ID>/report.json`、`preview.md` | 各次运行结果、复用数量、状态与预览内容 |
| `archive.lock` | P1 CLI、P2、P3、P5 和备份共用，活跃进程持有时拒绝并发启动 |

状态流程为 `pending → writing → previewed / failed / unknown`。先把 writing 原子入账再调用本地写入；进程中断留下 writing 时，恢复改为 unknown，不认为文件一定写成功或写失败。状态转换记录包含时间、尝试次数和固定错误码，恢复后仍可看到以前的失败或取消。

```powershell
# 已知失败/取消：只恢复本次任务的待处理或已知失败项，默认最多3次
pnpm run assistant notify --resume <P5运行ID>

# 未知：核对文件；不会重新写文件
pnpm run assistant notify --reconcile <通知ID>

# 诊断记录的恢复/核对同样显式 --purpose diagnostic
```

文件内容匹配可恢复为 previewed；文件确实缺失标为 failed，随后才允许显式 resume；文件内容冲突保持 unknown，不覆盖手工修改。达到重试上限后保留失败，不清零次数或无限重试。准备阶段失败需要修复输入后重新 preview；没有完整输入时不能以空通知视为成功。

`--status` 显示所选用途最近 10 次记录及总通知状态，`--verify` 核验两种用途的账本和全部成功回执。账本损坏明确失败，不自动清空。存储介质不可写时最多只能返回 CLI 错误，不能承诺还能在同一介质写入故障日志。

恢复复用原任务中的通知内容，不重新查询网站或重新判断旧临期文本；查看 `referenceTime`、源 P3 窗口和原站最新公告，不能把历史待处理消息当成当前截止状态。
