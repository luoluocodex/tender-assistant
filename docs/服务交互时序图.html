TENDER ASSISTANT / INTERACTION SEQUENCES

从一句请求，到一份有据可查的清单

使用者在 Codex 或 WorkBuddy 中提出任务，宿主通过技能调用本机统一程序。采集与附件模块访问政府网站；AI 分析由当前宿主会话完成；证据、结果和通知预览保存在本机。

参与方与职责边界

参与方职责与交互运行 / 保存位置
使用者指定任务、选定附件；在需要时处理登录或验证码；复核来源、完整性及业务判断。宿主界面；人工接管时使用专用浏览器与终端。
Codex / WorkBuddy读取 SKILL.md，解释任务并执行工具调用；读取结构化结果；当前会话完成 AI 判断。桌面宿主及其配置的模型服务。两者是可选入口，不需要互相调用。
技能包装器与统一入口tender.ps1 读取项目和 Node 绑定、检查版本、编译源码，再运行 assistant CLI；CLI 将命令交给 P1 / P2 / P3 / P5。skills/tender-assistant/ 是源码；安装副本在用户的 .codex/skills/ 或 .workbuddy/skills/。
本地业务程序P1 采集、P2 归档解析、P3 规则和分析校验、P5 预览。变更数据的命令通过公共归档锁互斥。本机 Node.js ≥ 24.13.0；同一套源码，非宿主安装缓存中的独立业务副本。
浏览器 / 下载器P1 用 Playwright Library 控制有头 Chromium；P2 常规下载用 Node fetch，人工认证时打开独立持久浏览器会话。本机；专用会话按来源和账号别名隔离。
政府门户与附件来源中国政府采购网与广东省公共资源交易平台提供搜索和公告。附件仅访问由真实公告确认、在配置中登记的来源。www.ccgp.gov.cn / search.ccgp.gov.cn、ygp.gdzwfw.gov.cn；已登记附件来源为 download.ccgp.gov.cn、gdgpo.czt.gd.gov.cn。
宿主使用的模型服务在宿主会话读取的上下文中做相关性判断、摘要和资格解释。本地程序没有直接请求另一套模型 API。具体服务与数据处理规则依宿主配置；图示为逻辑边界，不声称已抓包核实厂商内部协议或部署位置。
本地证据与存储P1 保存报告和页面证据；P2 保存原文件、解析和 SQLite 索引；P3 保存证据包和分析历史；P5 保存账本、预览及回执。P1：项目 output/playwright/；P2 / P3 / P5：C:\Users\14629\AppData\Local\TenderAssistant。两种宿主默认共享此数据根。

当前约束与已验证范围

事项当前事实
查询天数与 90 天上限宿主将“最近三天”等用户表述转换为 collect --days 3。允许 1～90 个自然日（含当天）；未指定时读取 config/p0-baseline.json 的默认 7 天。超过 90 天提示并拒绝，不截断、回退或拆分绕过。新报告的 queryDays/window 记录实际范围；本次参数不改写默认配置。
采集成功的含义列表候选不等于有效商机；详情按上限抽样。零结果、部分完成、正文缺失和附件失败分别记录；不能凭日期排序就无条件宣称某段时间完整。
WorkBuddy 验证2026-09-24 已验证本机技能识别、doctor 和前三条正式结果读取；这是宿主入口的只读验证，不代表 WorkBuddy 下重新跑过完整采集、登录与分析。
登录与 AI 分析真实政府账号、跨日会话和 CA / UKey 未验收。未分析的候选保持 pending；真实公司资料入口未启用，资料不足时不给出“符合”结论。
通知与调度仅 local-preview。外部发送与周期调度关闭；生成文件不等于邮件、企业微信等渠道已送达。
